How Bee was built, end to end

An 80M-parameter language model trained from scratch on a single Colab GPU: data, tokenizer, pretraining, two SFT stages and a tool-calling stage. Drag the model to rotate it, tap a layer to inspect it.

1 · Data: what we collected and how much

Pretraining corpus: 2,470,701 documents · 4.9 GB · ≈1.27B tokens

Bar = share of documents. Token budgets set per source (chars ÷ 4): Wikipedia 600M, Books 600M, Code 300M, Stories 200M, Jokes 5M, Poems 5M. Books is few documents but very long ones.

Sources

  • Wikipedia (20231101 English dump), Project Gutenberg books, CodeParrot-clean (Python), TinyStories, short jokes, Gutenberg poetry
  • Each source: download to local disk → extract and filter → write small .jsonl to Drive → delete raw files

Cleaning

  • Drop text under 20 characters; code files over 8,000 characters
  • Collapse whitespace; MD5 de-duplication on normalised text
  • Profanity filter on jokes, poems and chat data (LDNOOBW list + better-profanity)

SFT (chat) data: 450,034 examples · 738 MB

  • SQuAD Q&A (87,448), OpenAssistant (47,257 pairs + 16,702 multi-turn threads), Dolly (14,403)
  • Plus GSM8K, no_robots, CNN/DailyMail and SAMSum summaries, Orca system prompts, Python instructions, WritingPrompts, SST-2, CommonsenseQA
  • 25 hand-written persona chats and 60 refusal / clarify pairs ("I can't see live scores")

Also collected

  • 172,706 DPO preference pairs (hh-rlhf 159,849 · Orca 12,857)
  • 16,710 reasoning traces (Bespoke-Stratos, ≈70M tokens)
  • The notebooks shared here do not train on these two sets.

2 · Tokenizer

TSentencePiece BPE · 32,000 tokens

  • byte_fallback on and full character coverage: any text encodes, no <unk> loss
  • Trained on 1,479,003 lines (2.2 GB): all SFT, reasoning and DPO text plus every 5th pretraining document
  • Special tokens are atomic: <|user|>=4 <|assistant|>=5 <|system|>=6 <|end|>=7

σSizing the model

  • Chinchilla rule of thumb ≈ 20 tokens per parameter: 1.28B tokens → ≈64M params (range 32–96M)
  • Chose ≈80M: 14 layers, d_model 640. The 32k × 640 embedding alone is 20.5M, tied with the output head

▦Binary shards

  • Text → token ids stored as uint16 memory-mapped .bin files
  • Pretrain: 1,270,360,340 train + 6,383,721 val tokens (0.5%)
  • SFT: 173,846,113 train + 873,599 val tokens

3 · Training, stage by stage

1Pretraining · 20,000 steps

  • TensorFlow/Keras, float32 (mixed precision gave NaNs), single Colab T4
  • Batch 16 × 4 accumulation × 512 tokens = 65,536 tokens/step → 1.31B tokens, ≈1.03 epochs
  • AdamW (β 0.9/0.95, wd 0.1), LR 1e-4 → 1e-5, 500 warm-up steps cosine decay, grad-clip 1.0, NaN guard
  • Val loss 6.26 → 2.847 best at step 18,250. Colab restarts caused gaps in the log (see Benchmark)

2SFT stage 1 · chat format

  • PyTorch, torch.compile, fp16 autocast, starting from the pretrained weights
  • Format <|user|> … <|end|> <|assistant|> … <|end|>; loss only on assistant tokens
  • 8,000 steps ≈ 1.5 epochs of 173.8M tokens, 64 sequences/step, LR 1e-4 → 1e-5
  • Best val loss 2.689 at step 6,600; it flattened at ≈2.70 afterwards

3SFT stage 2 · identity and facts patch

  • 300 steps from the stage 1 best, LR 3e-5 → 3e-6
  • Every batch: 50% new (identity, capitals, abbreviations, simple maths, live-data refusals), 50% old chat data to avoid forgetting
  • New-data loss 2.68 → 1.35 within 25 steps; "Who made you?" now answers "Jalpit"

4Tool-calling SFT

  • Data: 14,000 synthetic examples with exact tool results (8 tools: calculator, weather, time, units, web search, reminder, random number, days between) + Glaive function-calling. After dropping rows over 512 tokens: 16,779 examples, 13,555 with a call
  • Format: <tool_call>{"name":…,"arguments":{…}}</tool_call>, result returned in <tool_response>, then Bee writes the answer
  • 3,000 steps, 60% tool data / 40% old chat data, LR 5e-5 → 5e-6. Tool val loss 2.74 → 0.14; best checkpoint chosen at step 2,500
  • Held-out synthetic test: 100% valid JSON, 100% right tool, 95.8% right tool + arguments, 100% correct "no tool needed". Remaining errors are digit slips (429/12 for 429/11)

5Serving

  • Flask app, KV-cache generation (self-tested against the full forward pass), 512-token window
  • Tool calls decoded greedily; tools run safely server-side (AST calculator, Open-Meteo weather, DuckDuckGo / Wikipedia search)
  • Small model, so the app drops old turns and limits each visitor to a daily token budget

Honest summary: behaviour (identity, format, tool calling) is learned well; world knowledge and arithmetic are not. At 80M parameters and ≈1.3B tokens that is expected.

Privacy Policy

Last updated: November 7, 2026

For learning purposes only. Bee is an educational experiment (an 80M-parameter model trained on a single GPU). It is not a product, and you cannot use this model in production: not in any commercial service, customer-facing app, or decision that affects people, money, health, safety or legal matters. It is often wrong, and nothing it says should be relied on.

1. What this site is

A personal demo of a small language model. There are no accounts, no ads, and no selling or sharing of data for marketing. It is run by for study and portfolio use.

2. What is collected when you chat

  • Your messages and Bee's answers, plus the model used, tools called, token count, time, and whether it was a retry. The site owner can read these in an admin panel. Do not type personal, confidential or sensitive information.
  • An anonymous visitor ID in a signed cookie (up to 1 year), used only to apply the usage limit (2,000 tokens per visitor per 12 hours) and to group your chats in the logs. It is not linked to your name.
  • Your IP address is used briefly in memory to slow down repeated admin-login attempts. It is not saved in the chat logs.
  • Browser storage: your settings (model, tools, creativity, length) are kept in your browser's localStorage. Your conversation itself stays in the page and is not saved there.

3. Third parties

  • Web search tool: your query is sent to DuckDuckGo, or Wikipedia as a fallback. Weather tool: the city name goes to Open-Meteo. These services have their own policies.
  • Page assets load from Tailwind CDN, Google Fonts and cdnjs (Three.js), which can see your IP address and browser details like any website you visit.
  • Your text is processed by the model on the owner's own machine. It is not sent to an AI company.

4. Retention and deletion

Logs are kept in a file on the owner's server until deleted. To have your chats removed, contact the owner (see About) with the time of your chat, since logs are tied to an anonymous ID and not to you. You can also clear your cookies and site data at any time.

5. Limits of the model

  • Bee can be wrong, make things up, and repeat itself. In the owner's own test it answered only about 20% of fixed questions correctly.
  • It must not be used for medical, legal, financial or safety advice.
  • The model weights and this site are provided as is, with no warranty, and are not licensed for production or commercial use.

6. Children

The site is not directed at children under 13. Please do not enter anyone's personal information.
